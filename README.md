# WalletEgg（資產負債看板）

個人資產負債總覽網頁 App（PWA，可安裝到主畫面並離線使用），專為手機（iPhone Safari）瀏覽設計，資料完全儲存於瀏覽器本地（IndexedDB），不上傳至任何伺服器。

## 技術架構

- 純 HTML + CSS + JavaScript，**不需 npm / build 工具**
- [Vue 3](https://vuejs.org/) **3.5.44**（全域版本，存放於 `vendor/vue.global.prod.js`）
- [PapaParse](https://www.papaparse.com/) **5.7.0**（存放於 `vendor/papaparse.min.js`，處理 CSV 匯入/匯出）
- PWA：`manifest.webmanifest`、`sw.js`（Service Worker 離線快取）、`js/pwa.js`（註冊、新版提示、安裝）、`icons/`（荷包蛋圖示）
- 資料儲存：瀏覽器 IndexedDB（資料庫名稱 `my_asset_dashboard`，見 `js/db.js`；改名為 WalletEgg 後**刻意不更改**，避免既有資料讀不到）
- 部署：GitHub Pages（純靜態檔案）

選擇免 build 方案的原因：避免本機/公司網路環境的憑證與套件安裝限制，同時降低維護成本（無需 `npm install`、無版本相依問題）。
第三方函式庫改為鎖定版本並放在 `vendor/`，以支援完全離線；升級時請下載新版檔案替換，並同步更新本節版本號與 `index.html` 中 vendor 的 `?v=`。

> **發版必讀（修改任何 app shell 檔案後）**：`index.html` 以 `<script src="js/xxx.js?v=版本號">` 引入本地程式檔，
> 每次修改 `js/pwa.js`、`js/store.js`、`js/db.js`、`js/services.js`、`js/app.js`、`css/style.css` 任何內容後，
> **務必同步更新這些 `<script>` / `<link>` 標籤的 `?v=` 版本號，並同時更新 `sw.js` 的 `APP_VERSION`**。
> 只有 `sw.js` 內容變動，已安裝的使用者才會收到新版（畫面會出現「有新版本，點此更新」提示條）；
> 若忘了更新 `APP_VERSION`，Service Worker 會一直提供舊版快取。另外，新增或刪除 app shell 檔案時，也要同步調整 `sw.js` 的 `SHELL_FILES` 清單。
> `?v=` 仍是必要的：它讓 GitHub Pages 邊緣 CDN 或尚未啟用 Service Worker 的瀏覽器也不會沿用舊版快取，
> 避免「畫面（HTML）已更新、但實際執行邏輯仍是舊版」的不一致現象（例如設定頁選項已改變，
> 但實際查詢行為看起來像沒套用新設定）。若懷疑遇到此情形，可請使用者先到「設定 > App > 檢查更新」，
> 或強制重新整理（iOS Safari：長按重新整理鈕選「重新載入無快取內容的網頁」），排除快取因素後再回報問題。

## 本地開發/預覽

任何靜態檔案伺服器皆可，例如：

```powershell
# Python
python -m http.server 8765

# 或使用 VS Code 的 Live Server 擴充功能
```

開啟瀏覽器至 `http://localhost:8765`。

> 不可直接用 `file://` 開啟 `index.html`，部分瀏覽器會擋下模組化的 fetch/CSV 檔案操作，請務必透過本地伺服器預覽。

### 我的負債顯示

- 比例條下方的帳戶名稱、色點與整數百分比沿用我的資產圖例樣式。
- 負債列表沿用資產的分隔線、開關、群組標頭及帳戶列樣式，不另包整份列表的大卡片。標頭顯示「負債帳戶」及「總負債金額 · 帳戶數 筆」，筆數為目前顯示的帳戶數，非明細紀錄數；無帳戶時顯示空資料提示。
- 每個帳戶依序顯示比例圓圈、帳戶名稱與金額。比例為「該帳戶計入金額 ÷ 總負債」，金額沿用現有本位幣估值；總負債小於或等於 0 時比例為 0%。負比例與超過 100% 的比例不另行截斷，整數百分比合計不強制補成 100%。
- 開啟「顯示不計入帳戶」只擴大列表範圍，不影響總負債與比例條；只含不計入紀錄的帳戶顯示 0 元及 0%。點擊帳戶仍開啟原有還款／編輯／紀錄彈窗。

### 投資交易手續費與計算機預帶

- 投資「增減 > 調整資訊」可輸入交易手續費，以投資與交割帳戶的相同幣別計價，不換匯；預設 0、留空視為 0，僅接受有限非負金額，最多小數 2 位。輸入不合法時會顯示原因並停用確認按鈕。
- 交割淨金額＝帶正負號的交易金額 − 手續費：買入為 `−數量 × 成交價格 − 手續費`，賣出為 `＋數量 × 成交價格 − 手續費`。例如成交總額 1,000、手續費 10，買入扣 1,010，賣出入帳 990。交割紀錄單位數再除以交割帳戶單價，沿用小數 6 位四捨五入。
- 手續費可大於成交總額（賣出可能變成淨扣款）。手續費大於 0 時必須指定交割帳戶；費用為 0 時仍可不指定。費用不改變投資持有數量、成交價，也不新增餘額不足限制。
- 同一彈窗切換買賣會保留費用，關閉後重新開啟帳戶彈窗則重設為 0。手續費只反映在交割帳戶差額紀錄，未新增獨立歷史／CSV 欄位；備份與還原保留淨交割結果，無法獨立查詢或還原費用。
- 數量計算機在欄位空白時，非投資預帶「目前餘額」（金額），投資預帶「目前持有」（單位數）。非投資單價不為 1 時，餘額與持有數量不同；計算結果帶回時不額外換算，請自行確認單位。

### 資料欄位（明細）

類型、帳戶/項目、日期、備註、單價、幣別、匯率、單位數、金額、槓桿率（曝險金額為計算欄位）。

日期欄儲存格式為 `yyyy-mm-dd hh:mi:ss`（本地時間）：舊資料（純日期）於啟動載入時自動補上 ` 00:00:00` 並一次性寫回 IndexedDB；畫面顯示、日期篩選與日期選擇器仍只使用日期部分（`yyyy-mm-dd`）。CSV 匯出含時分秒，匯入同時接受 `yyyy-mm-dd`、`yyyy/mm/dd` 與含時分秒的格式。

  Proxy／自訂 API，三者互相解耦，可自由組合：

  | 設定項目 | 說明 |
  |------|------|
  | Provider（資料來源） | 台股：`twse`（TWSE OpenAPI，官方，當日快照）／`yahoo`（Yahoo Finance）／`custom`（自訂 API）／`manual`（手動輸入）。美股：`finnhub`（需申請 Key）／`yahoo`／`custom`／`manual` |
  | Connection（連線模式） | `direct`（瀏覽器直接連線）或 `proxy`（經使用者自行設定的 Proxy URL 轉發）；`manual` 時不顯示 |
  | Proxy URL | `connection = proxy` 時使用，**本專案不內建任何公開 CORS proxy**，需自行填入，格式如 `https://your-worker.example.workers.dev/?url={url}`（`{url}` 會被取代為編碼後的目標網址）；建議自建 Cloudflare Workers，見 [`docs/cloudflare-worker-proxy-佈建手冊.md`](docs/cloudflare-worker-proxy-佈建手冊.md) |
  | 自訂 API URL / JSON Path | `provider = custom` 時使用；URL 樣板含 `{symbol}` 佔位字（例：`https://example.com/api/quote?symbol={symbol}`），JSON Path 以 `.` 分隔（例：`data.quote.close`、`chart.result.0.meta.regularMarketPrice`），僅支援簡單欄位/陣列索引解析，**不使用 eval 或任意 JS parser** |
  | Finnhub API Key | 美股 `provider = finnhub` 時使用，於 [finnhub.io](https://finnhub.io/register) 免費申請；Key 僅存於本機瀏覽器，且不會出現在畫面、Log、匯出 JSON、Console 中（一律顯示 `******`） |

  > `connection = proxy` 才能查詢；美股 `Finnhub` 原生支援 CORS，是唯一可用 `direct` 連線的自動查詢來源。
  > 舊版內建的公開 CORS proxy（corsproxy.io / allorigins.win / thingproxy.freeboard.io）已全數移除
  > （corsproxy.io 已改為需付費 API Key，其餘穩定性亦無法保證），改為完全由使用者自行配置 Proxy URL。

  設定完成後，建議至「設定 > 報價來源 > 連線測試」子分頁的「台股／美股設定測試」實際發出一次請求驗證（不會更新任何
  帳戶價格/明細資料），確認 Request URL／HTTP Status／Latency／Response Preview／Error Code 皆正常，
  再回到設定頁「同步」區塊按「同步價格」正式套用。「連線測試」也提供「任意 Endpoint 測試」，可自行輸入任意
  網址（搭配 direct/proxy 與選填 JSON Path）驗證連線是否可行，方便除錯自訂 API 或自建 proxy 是否設定正確。

於設定頁「同步」區塊可按「同步匯率」「同步價格」依上述設定一次更新，查詢失敗時請改回手動輸入。

### 明細與帳戶設定正規化（估值即時計算）

- 明細（`records`）只保存交易事實：`id`、`type`、`account`、`date`、`note`、`units`、`excluded`、`currency`、
  `tradePrice`（成交價）、`tradeFxRate`（成交匯率），不再保存價格、匯率、槓桿倍數與金額。
- 估值一律即時計算：金額 = 有效價格 × 單位 × 有效匯率；曝險金額 = 金額 × 有效槓桿倍數。
  - 有效價格／槓桿倍數：有對應「資產帳戶」設定時取帳戶設定；否則價格取成交價（再沒有用 1）、槓桿倍數依類別預設（投資 1、其餘 0）。
  - 有效匯率：取「幣別」設定的匯率；查無幣別時取成交匯率（再沒有用 1）。
  - 有效幣別：有對應帳戶時取帳戶幣別，否則取明細幣別（明細頁的幣別只在未對應帳戶時可選）。
- 因此「同步匯率」「同步價格」、手動修改匯率／價格／槓桿倍數、或「從資產帳戶CSV還原」後，所有畫面立即反映，不需再套用至明細。
- 修改「資產帳戶」的帳戶/項目名稱時，相同名稱的明細會一併改名。
- 成交價／成交匯率只作歷史紀錄（顯示於明細頁與帳戶彈窗 [紀錄]），不參與已對應帳戶的估值。
- **一次性遷移（無法回退）**：舊版資料開啟時會自動把 `unitPrice` 搬到 `tradePrice`、`fxRate` 搬到 `tradeFxRate`，
  並刪除 `leverage`／`amount` 後寫回 IndexedDB。舊版程式讀取遷移後的資料金額會變成 0，升級前建議先「匯出備份CSV」。
- 明細 CSV 欄位：「價格／匯率／槓桿倍數／金額／曝險金額」匯出的是實際估值使用的有效值，並新增「成交價／成交匯率」欄位；
  匯入時成交價優先讀「成交價」欄（舊版 CSV 退回「價格」欄），成交匯率優先讀「成交匯率」欄（退回「匯率」欄），
  「槓桿倍數／金額／曝險金額」欄位忽略。舊版 CSV 仍可匯入。

## 部署到 GitHub Pages

1. 建立 GitHub repo（public，免費方案 GitHub Pages 僅支援 public repo）
2. 將本目錄內容 push 到該 repo 的 `main` 分支
3. Repo → Settings → Pages → Source 選擇 `main` branch / `root`
4. 幾分鐘後即可透過 `https://<username>.github.io/<repo>/` 存取
5. `manifest.webmanifest`、`sw.js` 都使用相對路徑（`./`），可直接部署在子路徑，不需修改；`sw.js` 必須放在網站根目錄（與 `index.html` 同層），Service Worker 才能涵蓋整個 App

## PWA：安裝與離線

- **安裝**
  - Android / 桌機 Chrome、Edge：到「設定 > App」按「安裝 WalletEgg 到裝置」，或從瀏覽器選單選「安裝應用程式」。
  - iPhone / iPad：以 Safari（或 iOS 16.4 以上的 Chrome / Edge）開啟 → 「分享」→「加入主畫面」。
- **離線**：首次連網開啟後，`sw.js` 會預先快取 app shell（HTML / CSS / JS / vendor / 圖示），之後離線也能開啟並讀寫 IndexedDB 資料。
  匯率、股價等**跨網域 API 請求不經過 Service Worker 快取**，一律即時連網，因此離線時「同步匯率 / 同步價格」會失敗，這是預期行為。
- **更新**：偵測到新版時，畫面底部會出現「有新版本，點此更新」提示條，點擊後重新載入一次即套用新版。
  App 回到前景時會自動檢查（間隔至少 60 秒），也可以到「設定 > App > 檢查更新」手動檢查。
- **持久儲存**：啟動時會呼叫 `navigator.storage.persist()`，降低瀏覽器在空間不足時清除資料的機率，但這不能取代定期匯出 CSV 備份。
- **圖示**：母版為 `icons/icon.svg`（主體在 maskable 安全區內）；PNG 由此 SVG 輸出（192 / 512 / apple-touch 180 / favicon 32），修改圖示後需重新輸出 PNG。
- **本機測試**：Service Worker 只能在 HTTPS 或 `localhost` 下運作，請用 `python -m http.server` 預覽。開發時若想避免被快取干擾，
  可在 Chrome DevTools > Application > Service Workers 勾選「Update on reload」。

## 資料備份與風險提醒

所有資料僅存在單一瀏覽器的 IndexedDB（資料庫 `my_asset_dashboard`，四個 object store：`records`、`settings`、`accounts`、`syncLogs`）：

- 清除瀏覽器資料、換裝置、換瀏覽器（含 Safari 無痕模式）都會遺失資料
- **請定期使用「設定 > 資料管理」的「匯出備份CSV」與「設定 > 資產帳戶設定」的「匯出資產帳戶CSV」功能備份**
- `syncLogs`（同步記錄）為選用性除錯資訊，一般同步需於「設定 > 資料管理」的「Log 紀錄」開關手動開啟才會寫入
  （「連線測試中心」的測試結果不受此開關限制、一律會寫入），僅保留最近 500 筆、單筆內容最長 5000 字、
  全部記錄總內容不超過 500000 字，可另外「匯出 Log（JSON）」或「清除 Log」，不影響其餘資料備份/還原流程
- **錯誤記錄（error log）**：畫面錯誤橫幅顯示過的所有錯誤（JS 執行期錯誤、未處理的 Promise、CDN 載入失敗、Vue 元件錯誤、
  匯入/匯出/同步/清除等失敗、IndexedDB 寫入失敗），以及同步價格/匯率的個別項目失敗（不受 Log 紀錄開關影響），
  會寫入 **localStorage** 鍵 `ald_error_logs`（不在 IndexedDB 內），最多 1000 筆、單筆最長 5000 字，超過時捨棄最舊的。
  於「設定 > 資料管理 > 錯誤記錄」可查看（新到舊，點擊展開全文）、匯出 JSON、清除；「清除所有資料」**不會**清除錯誤記錄。
  注意：localStorage 與 IndexedDB 一樣以 origin 隔離，若與 `asset-liability-dashboard_2` 部署在同一網域，會共用同一份錯誤記錄。

### CSV 匯入模式（沿用既有行為，未變更）

- 「從備份CSV還原」（明細）與「載入模擬資料」皆為**附加**：會加在現有明細之後，**重複匯入會產生重複資料**，不會自動去重。
- 「從資產帳戶CSV還原」為**取代**：會整批覆蓋現有的帳戶/項目設定（匯入前會再次跳出確認），完成後明細估值立即改用新的價格與槓桿倍數。
- 若要用備份 CSV 還原改版前的資料，建議先在「設定 > 資料管理」按「清除所有資料」清空後，再匯入 CSV。

### 系統設定（settings）不包含在 CSV 內，需手動重新設定

明細 CSV 與帳戶設定 CSV 只涵蓋各自的資料列，以下 `settings` 項目不會被匯出/匯入，換裝置或清除資料後需自行於「設定」頁重新設定：

- 顯示單位（元 / 萬元）
- 主題模式（深色 / 淺色）
- 主題配色（含自訂配色）
- 字型與字型大小
- 投資配置比（再平衡目標比例）
- 幣別清單與各幣別匯率、基準幣別
- 資產子類別顯示名稱（自訂類別名稱）
- 股價資料來源設定（台股/美股 Provider、Connection、Proxy URL、自訂 API URL/JSON Path、Finnhub API Key）
- 資產頁「顯示不計入帳戶」開關

## iPhone 使用注意事項

- 已加入 `viewport-fit=cover` 與 `env(safe-area-inset-*)` 處理瀏海/底部安全區域
- 已加入 `apple-mobile-web-app-capable` meta、`apple-touch-icon` 與 `apple-mobile-web-app-title`（WalletEgg），可「加入主畫面」以全螢幕 App 方式開啟
- **主畫面 App 與 Safari 分頁的資料互不共用**（各自獨立的 IndexedDB）：從 Safari 改用主畫面 App 前，請先在 Safari 匯出「備份CSV」與「資債類型帳戶CSV」，
  再於 App 內還原；系統設定不在 CSV 內（見上方清單），需手動重新設定
- Vue 3 需要 `Proxy` 支援，iOS Safari 10.3+ 皆相容，不需額外處理
